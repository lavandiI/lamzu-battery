# Python 1.5.11 против Rust 1.6.0: измерения

Сравнение зафиксировано до того, как Python-версия была удалена из репозитория
(её исходники остались в истории git).

Обе версии запускались на одной машине (Windows 11), с одним и тем же донглом
`3554:F50D` и мышью LAMZU Thorn, которая отдавала 89 %. Сравниваются именно
поставляемые артефакты — то, что видит пользователь:

- **Python**: `dist\LamzuBattery.exe`, PyInstaller onefile, версия 1.5.11.
- **Rust**: `dist\LamzuBattery.exe`, release (`lto = "fat"`,
  `opt-level = "s"`, `panic = "abort"`), версия 1.6.0.

## Методика

- По три запуска каждого приложения по 40 секунд, запуски чередовались, в
  таблице — медианы.
- «Готово» — момент, когда `data\status.json` впервые содержит `running: true`;
  «первое показание» — когда в нём появляется `online: true` и процент.
  Файл опрашивался каждые 150 мс.
- Память, потоки и хэндлы — `WorkingSet64`/`PrivateMemorySize64`/`Threads.Count`/
  `HandleCount` по дереву процессов (у PyInstaller это bootloader + ребёнок),
  каждые 150 мс, в таблице пик.
- CPU — `KernelModeTime + UserModeTime` из `Win32_Process`: отдельно стартовое
  окно (к 0,4 с) и простой в течение 55 секунд.
- Второй экземпляр — `Process.Start` + `WaitForExit`, три замера.
- Диагностика — пять запусков, медиана: `python diagnose.py --lang en` против
  `LamzuBattery.exe --diagnose --lang en`.
- Размер — файл на диске; распаковка — новые каталоги `%TEMP%\_MEI*` после старта.

## Что нашли и исправили в процессе

1. **HID-слой ждал весь таймаут.** Первая реализация `exchange` возвращала
   отчёты только по истечении 500 мс, даже если валидный кадр приходил сразу:
   `--diagnose` занимал 619 мс. Теперь `HidPort::exchange` останавливается на
   первом разбираемом кадре, а `probe` (режим `--raw`) по-прежнему собирает всё
   окно. Итог: диагностика 96 мс, латентность опроса — десятки миллисекунд
   вместо половины секунды.
2. **PyInstaller оставляет мусор при принудительном завершении.** После
   ~50 прерванных запусков в `%TEMP%` накопилось 96 каталогов `_MEI*` общим
   размером 711,7 МиБ. Это же происходит при штатном обновлении Python-версии,
   которое убивает процесс через `taskkill /T /F`. Rust ничего не распаковывает
   и такого мусора не оставляет.

## Оговорки

- Python-сборка упакована PyInstaller onefile, поэтому часть разницы — это
  распаковка 31 МиБ и второй процесс, а не только язык. Но пользователь
  сталкивается именно с этими артефактами.
- **CPU в простое у обеих версий одинаковый** (0,1–0,15 с за минуту). Его
  определяет перечисление HID раз в 5 секунд, и это поведение специально
  сохранено паритетным. Выигрыш Rust — старт, память, размер и латентность,
  а не установившийся CPU.
- Один прогон Python показал 42 с до первого показания: мышь спала, и первые
  два опроса (интервал 20 с) остались без ответа. Обе версии ведут себя
  одинаково; выброс из медиан исключён.
- Абсолютные значения зависят от машины и момента; значимы отношения.
